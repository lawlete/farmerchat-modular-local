La aplicación almacena la base de datos automáticamente en el localStorage del navegador web.
No se trata de una "carpeta" en el sistema de archivos de tu dispositivo como ocurriría con una aplicación de escritorio tradicional. En cambio, localStorage es un mecanismo de almacenamiento que los navegadores proporcionan a las páginas web para guardar datos de forma persistente en el dispositivo del usuario.
Cómo funciona:
Guardado: Cada vez que realizas cambios en los datos (crear, actualizar, eliminar entidades, o importar archivos), la aplicación actualiza su estado interno y luego guarda una representación completa de la base de datos (en formato JSON) en localStorage bajo una clave específica (actualmente farmerChatDB_v5).
Carga al inicio: Cuando abres o reinicias la aplicación, esta intenta cargar los datos desde localStorage usando esa misma clave. Si encuentra datos guardados, los utiliza para reconstruir el estado de la base de datos, permitiéndote continuar donde lo dejaste. Si no encuentra nada (o si los datos están corruptos), comienza con una base de datos vacía.
Puntos clave sobre localStorage:
Específico del navegador y del origen: Los datos guardados en localStorage por una aplicación web solo son accesibles por esa misma aplicación cuando se ejecuta desde el mismo origen (protocolo, dominio y puerto). Otras páginas web o aplicaciones no pueden acceder a ellos.
Limitaciones de tamaño: localStorage tiene un límite de almacenamiento (generalmente alrededor de 5-10 MB por origen), lo que es suficiente para este tipo de aplicación de simulación, pero podría ser una limitación para bases de datos extremadamente grandes.
Persistencia: Los datos permanecen guardados incluso después de cerrar el navegador o reiniciar el dispositivo, hasta que se limpian explícitamente (ya sea por el usuario a través de las herramientas del navegador o por la propia aplicación).
Puedes inspeccionar el contenido de localStorage en las herramientas de desarrollador de tu navegador (generalmente en la pestaña "Application" o "Storage").

Cuando ejecutas la aplicación como una PWA en un dispositivo móvil, la persistencia de los datos de la "base de datos" (que en esta aplicación es un objeto JavaScript) se gestiona principalmente a través de la API localStorage del navegador. 
Aquí te detallo el proceso:
¿Qué es localStorage?
localStorage es una API de almacenamiento web que permite a las aplicaciones web guardar datos (en formato de cadenas de texto) en el navegador del usuario de forma persistente.
Los datos almacenados en localStorage persisten incluso después de cerrar el navegador o reiniciar el dispositivo.
Cada origen web (combinación de protocolo, dominio y puerto) tiene su propio localStorage aislado. Esto significa que los datos de tu PWA no pueden ser accedidos por otros sitios web y viceversa.
PWA y localStorage en Móviles:
Cuando "instalas" una PWA en un dispositivo móvil (por ejemplo, a través de "Añadir a pantalla de inicio" en Android), la PWA sigue ejecutándose dentro del motor del navegador web del dispositivo (por ejemplo, Chrome para Android).
Por lo tanto, el comportamiento de localStorage es idéntico al que tendría si estuvieras accediendo al sitio web desde la pestaña del navegador en ese mismo dispositivo.
Los datos se guardan localmente en el almacenamiento del dispositivo, gestionado por el navegador.
Cómo lo implementa esta aplicación:
Clave de Almacenamiento: La aplicación utiliza una clave específica en localStorage, definida en constants.ts como LOCAL_STORAGE_DB_KEY (actualmente 'farmerChatDB_v5').
Serialización: El estado completo de la base de datos (el objeto database en App.tsx) se convierte en una cadena de texto en formato JSON usando JSON.stringify(database) antes de guardarlo. Esto es necesario porque localStorage solo puede almacenar cadenas.
Guardado: Cada vez que el objeto database en el estado de React se modifica (por ejemplo, al crear un nuevo cliente, registrar una tarea, importar datos), el useEffect en App.tsx que vigila los cambios en database se activa:
useEffect(() => {
  localStorage.setItem(LOCAL_STORAGE_DB_KEY, JSON.stringify(database));
}, [database]);

TypeScript
Si encuentra datos bajo la clave LOCAL_STORAGE_DB_KEY, los convierte de la cadena JSON de vuelta a un objeto JavaScript usando JSON.parse() y los utiliza para inicializar el estado database de la aplicación.
Funcionamiento en la PWA Móvil:
Al abrir la PWA en tu móvil, se ejecuta el código de App.tsx.
La aplicación intenta cargar los datos desde el localStorage del navegador del móvil.
Si ya has usado la app antes en ese dispositivo y se han guardado datos, estos se cargarán y estarán disponibles.
Cualquier cambio que hagas (añadir un cliente, registrar una tarea, etc.) se guardará automáticamente en el localStorage del dispositivo.
Si cierras la PWA y la vuelves a abrir, los datos persistirán porque fueron guardados localmente.
Consideraciones y Limitaciones:
Capacidad: localStorage tiene un límite de almacenamiento, generalmente entre 5MB y 10MB por origen, dependiendo del navegador y el dispositivo. Para una cantidad muy grande de datos agrícolas, esto podría ser una limitación.
Sincronización: Los datos en localStorage son estrictamente locales a ese dispositivo y ese navegador. No hay sincronización automática con otros dispositivos ni con un backend en la nube. Si usas la PWA en tu teléfono y luego en una tablet (incluso si es la misma "app" instalada), tendrán bases de datos separadas en localStorage. Las funciones de importación/exportación de JSON/CSV son la forma manual de mover datos entre dispositivos o realizar copias de seguridad.
Limpieza de Datos: El usuario puede borrar los datos almacenados por la PWA si borra los datos del navegador o los datos específicos de la "aplicación instalada" a través de los ajustes del sistema operativo del móvil.
No es una Base de Datos Real: localStorage es un simple almacén de clave-valor. Todas las operaciones de "consulta" o filtrado se realizan en la memoria de la aplicación después de cargar todos los datos.
En resumen, la persistencia en la PWA móvil se basa en localStorage, que guarda una representación JSON de toda tu base de datos directamente en el almacenamiento del dispositivo, gestionado por el navegador. Esto permite que los datos sobrevivan entre sesiones en ese dispositivo específico.

Protocolo de Pruebas de Persistencia de Datos (localStorage)
Objetivo: Verificar que los datos ingresados y modificados en la aplicación persisten correctamente después de cerrar y reabrir la aplicación, tanto en un navegador de escritorio como en un dispositivo móvil (PWA).
Entorno de Pruebas:
Navegador de Escritorio: Google Chrome (recomendado por sus herramientas de desarrollo), Firefox, o Edge.
Dispositivo Móvil: Un smartphone Android con un navegador compatible con PWA (ej. Chrome para Android).
Parte 1: Prueba en Navegador de Escritorio
Pasos:
Preparación:
Abre la aplicación en tu navegador de escritorio (ej. http://localhost:PUERTO).
Abre las Herramientas de Desarrollador (usualmente con F12 o click derecho > Inspeccionar).
Ve a la pestaña "Application" (en Chrome/Edge) o "Storage" (en Firefox).
En el panel izquierdo, bajo "Storage", expande "Local Storage" y selecciona el origen de tu aplicación (ej. http://localhost:PUERTO).
Deberías ver una clave llamada farmerChatDB_v5 (o la clave actual definida en LOCAL_STORAGE_DB_KEY). Si es la primera vez, el valor podría ser la base de datos inicial vacía o no existir aún hasta la primera modificación.
Ingreso y Modificación de Datos:
Interactúa con la aplicación para añadir nuevos datos. Por ejemplo:
Usando el chat: "Crear cliente llamado AgroTest con teléfono 123456789".
Verifica que el cliente "AgroTest" aparece en el panel de "Datos del Campo" y que la entrada en localStorage (clave farmerChatDB_v5) se actualiza. Puedes copiar el valor y pegarlo en un editor de texto para ver el JSON.
Crea algunas tareas o importa un pequeño archivo CSV de prueba para una entidad.
Realiza varias operaciones de creación o modificación. Por ejemplo, añade otro cliente, un campo, o una tarea.
Verificación de Guardado Inicial:
Observa el panel de "Datos del Campo" en la aplicación. ¿Refleja todos los cambios que hiciste?
En las Herramientas de Desarrollador, verifica que el valor asociado a la clave farmerChatDB_v5 en localStorage se ha actualizado y contiene los datos que ingresaste (en formato JSON).
Cierre de la Aplicación (Simulación):
Opción A (Cerrar Pestaña): Cierra la pestaña del navegador donde tienes la aplicación abierta.
Opción B (Cerrar Navegador Completo): Cierra completamente el navegador.
Reapertura y Verificación de Persistencia:
Vuelve a abrir el navegador (si lo cerraste) y navega nuevamente a la URL de la aplicación.
Verificación Visual:
Observa el panel de "Datos del Campo". ¿Aparecen los datos que ingresaste antes de cerrar (ej. el cliente "AgroTest", las tareas, etc.)?
Envía un mensaje al chat como "Listar todos los clientes". ¿Aparece "AgroTest"?
Verificación Técnica (Opcional pero Recomendado):
Abre las Herramientas de Desarrollador y revisa localStorage. ¿La clave farmerChatDB_v5 contiene los mismos datos que tenías antes de cerrar?
Prueba de Reseteo (Opcional):
En las Herramientas de Desarrollador, en la pestaña "Application" / "Storage", haz clic derecho sobre la clave farmerChatDB_v5 y selecciona "Delete" o usa el botón para limpiar localStorage para ese origen.
Refresca la página de la aplicación (F5).
Verifica que la aplicación se carga con la base de datos inicial (vacía o con los datos por defecto definidos en INITIAL_DB). Todos los datos previamente ingresados deberían haber desaparecido del panel de datos.
Parte 2: Prueba en Dispositivo Móvil (PWA)
Pasos:
Preparación:
Asegúrate de que tienes la PWA "instalada" en tu dispositivo Android. Si no, ábrela en Chrome (o el navegador compatible) y busca la opción "Añadir a pantalla de inicio" o "Instalar aplicación".
Cierra completamente la PWA si estaba abierta (desde el administrador de tareas/aplicaciones recientes del móvil).
Ingreso y Modificación de Datos:
Abre la PWA desde el icono en tu pantalla de inicio o cajón de aplicaciones.
Al igual que en el escritorio, interactúa con la aplicación para añadir nuevos datos. Por ejemplo:
"Crear cliente llamado MovilTest con email movil@test.com".
Verifica que el cliente "MovilTest" aparece en el panel de "Datos del Campo".
Registra una tarea simple: "Crear tarea de pulverización para el cliente MovilTest en el campo Norte, estado programada".
Verificación de Guardado Inicial (Visual):
Observa el panel de "Datos del Campo" en la PWA. ¿Refleja todos los cambios que hiciste?
Cierre de la Aplicación (Simulación Real):
Sal de la PWA (ej. yendo a la pantalla de inicio de tu móvil).
Importante: Para una prueba más robusta, fuerza el cierre de la PWA. Ve al administrador de aplicaciones recientes de tu teléfono y desliza para cerrar la PWA, o ve a Ajustes > Aplicaciones > [Nombre de tu PWA FarmerChat] > Forzar detención. Esto asegura que la aplicación no está simplemente en segundo plano.
Reapertura y Verificación de Persistencia:
Vuelve a abrir la PWA desde su icono.
Verificación Visual:
Observa el panel de "Datos del Campo". ¿Aparecen los datos que ingresaste antes de cerrar (ej. "MovilTest" y la tarea de pulverización)?
Envía un mensaje al chat como "Listar tareas para MovilTest". ¿Aparece la tarea registrada?
Prueba de Reseteo (Opcional en Móvil):
Esto es un poco más drástico en móvil pero útil para confirmar un estado limpio.
Opción A (Borrar Datos de la App): Ve a Ajustes del teléfono > Aplicaciones > [Nombre de tu PWA FarmerChat IA] > Almacenamiento > Borrar datos (o Borrar almacenamiento). Esto eliminará todo el localStorage y caché de la PWA.
Opción B (Desinstalar y Reinstalar): Desinstala la PWA desde el cajón de aplicaciones o ajustes. Luego, vuelve a acceder a la URL en el navegador e instálala de nuevo.
Después de cualquiera de estas opciones, abre la PWA. Debería cargarse con la base de datos inicial (vacía), y los datos de "MovilTest" no deberían estar presentes.
Resultados Esperados:
En ambos escenarios (escritorio y móvil), los datos ingresados deben persistir después de cerrar y reabrir la aplicación.
La eliminación manual de localStorage (o datos de la app en móvil) debe resultar en que la aplicación se cargue con un estado limpio o inicial.
Notas Adicionales:
Si estás usando el modo de incógnito/privado del navegador, localStorage podría no persistir de la misma manera o podría borrarse al cerrar todas las ventanas de incógnito. Realiza las pruebas en una sesión normal del navegador.
En el móvil, asegúrate de que el navegador tiene permisos de almacenamiento si es que los requiere explícitamente (generalmente no es un problema para localStorage).
La persistencia de localStorage es por navegador y por perfil de usuario en ese navegador. Si pruebas en Chrome y luego en Firefox en el mismo PC, tendrán almacenamientos separados.
Este protocolo debería darte una buena confianza en que la persistencia de datos de tu aplicación está funcionando como se espera.
